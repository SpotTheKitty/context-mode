# Workstation tenant HTTP fork

Build server-http.mjs and hook-http.mjs with node build/build-http.mjs. The HTTP endpoint, header, tenant adapters, timeouts, and data directory come from the caller-supplied workstation endpoint table. Both entries are flat bundles.

The stdio entry retains its original schema and operation. HTTP stores tenant/project-scoped journal, sources, metadata, and FTS rows in one SQLite database. A native one-shot hook posts its payload and tenant header to the shared server; transport failures use the upstream native failure policy. The HTTP listener supports _workspace and _sessionId tool arguments or corresponding request metadata. Machine-wide doctor and upgrade operations use stdio.
# One-time import

The flat `import.mjs <endpoint-table>` entry only plans; `--apply` imports read-only source snapshots into the shared SQLite file. `contextMode.imports` lists explicit old roots and their tenant. Missing roots are skipped; links inside a root are not followed. Original records are retained in the tenant/project-scoped `legacy_records` archive. Current journal/FTS rows retain their fields with remapped source IDs, and v1 session events become journal entries and searchable FTS content. Ancillary v1 session metadata, resume snapshots and tool counters remain in the archive. Derived trigram indexes are rebuilt.

Private v1 content filenames are matched to project directories from that tenant's session metadata using v1's documented canonical/legacy path hashes. Unavailable workspaces require `importProjectMappings` (old workspace to current workspace). An ambiguous or shared source requires `importDatabaseMappings`, keyed by its canonical absolute database path with forward slashes, with an explicit `tenant` and `workspace` or `projectKey`. A shared database must have one verified owner before using that whole-file mapping; mixed-owner files require a reviewed split before import. No ownership is inferred from the fact that several clients configured the same directory.

All sources are preflighted before destination creation. Each applied source is transactional; orphaned content rolls back its imported rows. A digest marker makes an unchanged rerun a no-op and rejects a changed source rather than synchronizing it. Quiesce the old writers and retain source backups during coordinator rollout. The importer never renames, checkpoints or writes a source database. Plans and tests do not run against the live workstation store.
